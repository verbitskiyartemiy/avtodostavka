# Discovery Kit — навигатор

Discovery Kit превращает идею в набор документов, готовых для передачи разработчику. Каждый шаг — отдельная команда `/dk-…`. Все документы проекта лежат в `discovery/` в текущей рабочей папке (если проектов несколько — `discovery/<проект>/`).

## Что делать при вызове

1. Посмотри, что уже есть в `discovery/` (если папки нет — это новый проект).
2. Коротко покажи пользователю статус: что готово ✅, что следующее ▶️. Без длинных таблиц — простым списком.
3. Предложи следующий шаг по порядку ниже и спроси, запускать ли его. Если пользователь описал идею в аргументах вызова — сразу переходи к `/dk-brief` с этим описанием.
4. Запуская шаг, вызывай соответствующий скилл (Skill tool), а не пересказывай его своими словами.

## Готовые маршруты — предложи подходящий

- **Минимальный до разработки:** бриф → USM → NFR → C4 → ER → проверка.
- **Проверка бизнес-идеи / кейс-чемпионат / питч:** бриф → Lean Canvas → рынок → персоны → интервью с персонами. Технические шаги не нужны.
- **Полный:** все шаги по порядку таблицы. Перед техническими шагами полезен `/dk-artifact-recommendation` — он скажет, какие из шагов 10–17 можно пропустить.

## Принципы кита (соблюдай на всех шагах)

- **Цикл уточнения:** спрашивай по одной теме, пока «неопределённость» не станет ≈ 0.02. «Не знаю» → разбей вопрос или дай варианты; «хватит вопросов» → зафиксируй как открытый вопрос и иди дальше.
- **Gold / Silver / Bronze** — варианты с разным уровнем амбиций для требований и технических решений.
- **В бизнес-шагах (бриф, USM, journey) — никаких технических решений.** Технологии — только с шага 9.
- **Ограничения** (бюджет, сроки, команда) — в брифе; **атрибуты качества** (скорость, безопасность) — в NFR.
