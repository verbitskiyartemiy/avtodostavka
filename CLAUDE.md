# Проект «Автодоставка»: автономный discovery-пайплайн

Студенческий проект (онбординг): приложение для покупки автомобилей из Кореи, Японии и Китая частными покупателями из России. Цель пайплайна — проработать проект по шагам Discovery Kit и в конце выдать **схематичный бриф презентации для дизайнера** (11 слайдов по ТЗ). Готовый .pptx НЕ делаем.

Работа идёт **автономно, без человека**: запуски по расписанию в облаке, каждый продолжает с места, где остановился предыдущий. Задавать вопросы некому.

## Файлы

- `input/avto-iz-azii-context.md` — исходный контекст команды. Опора проекта, но **не истина**: каждое утверждение проверяем, ставим под сомнение и исправляем, если данные говорят иное.
- `input/tz-presentation.md` — ТЗ на итоговую презентацию. `input/template-structure.md` — структура шаблона.
- `PIPELINE.md` — шаги, их задачи и чек-листы ревью. **Главная инструкция.**
- `STATUS.md` — состояние шагов и блокировка. Единственный источник правды о прогрессе.
- `discovery/` — артефакты шагов. `presentation/` — бриф презентации. `reviews/` — отчёты ревью.
- `.claude/skills/dk-*` — скиллы Discovery Kit.

## Протокол запуска

1. `git fetch origin && git checkout claude/discovery && git pull origin claude/discovery`. Работаем только в ветке `claude/discovery`.
2. Прочитай `STATUS.md` и `PIPELINE.md` целиком.
3. **Блокировка.** Если в `STATUS.md` строка `LOCK: busy since <UTC>` и с этого момента прошло меньше 100 минут — другой запуск ещё работает: ничего не меняй и заверши работу. Иначе запиши `LOCK: busy since <текущее UTC>` (`date -u +%Y-%m-%dT%H:%M:%SZ`), закоммить и запушь. Если push отклонён — кто-то успел раньше: заверши работу.
4. Выполни по порядку следующие шаги со статусом `TODO` — **не больше 5 шагов за запуск** (чтобы контекст оставался свежим; следующий запуск продолжит).
5. После каждого шага: ревью (см. ниже) → обнови строку шага в `STATUS.md` и обнови время в строке LOCK (это «пульс») → `git add -A && git commit -m "<шаг>: <что сделано>" && git push origin claude/discovery`.
6. В конце запуска поставь `LOCK: free`, закоммить, запушь.
7. Если все шаги `DONE` / `DONE_WITH_ISSUES` — ничего не делай и сразу заверши работу.

## Как выполнять шаг

- Если у шага указан скилл — вызови его (Skill tool) и следуй ему, с поправками ниже.
- **Автономный режим для скиллов Discovery Kit.** Скиллы написаны для диалога: задают вопросы, ждут ответов. Здесь отвечать некому. Вместо вопросов пользователю: (1) ищи ответ в `input/` и готовых артефактах `discovery/`; (2) ищи данные в интернете (WebSearch/WebFetch); (3) если данных нет — прими разумное допущение и пометь его `[ДОПУЩЕНИЕ]`. Цикл уточнения «неопределённость ≤ 0.02» проходи сам с собой; в конце документа — раздел «Допущения и открытые вопросы».
- Папка документов для скиллов — `discovery/` (не `discovery/<проект>/`).
- Где скилл предлагает спросить пользователя о выборе (платформа, вариант Gold/Silver/Bronze и т.п.) — выбирай сам, исходя из стадии проекта (студенческий проект, discovery, проверка гипотез, MVP с минимальным бюджетом), и обоснуй выбор одной строкой.

## Правила качества (обязательны на всех шагах)

1. **Источники.** Каждое число и каждый факт о рынке, законах, компаниях — с источником: `[ИСТОЧНИК: название, URL, дата]`. Нет источника — `[ДОПУЩЕНИЕ]` или `[ГИПОТЕЗА]`. Цифры не выдумывать.
2. **Реальные компании и конкуренты** — только найденные поиском, со ссылкой. Не приписывать компаниям цены, отзывы или факты без источника.
3. **Симуляции.** Всё, что получено симуляцией (интервью с персонами), помечать `[СИМУЛЯЦИЯ]` и никогда не выдавать за реальные интервью или реальные данные. Реальных интервью у команды пока нет.
4. **Критичность к исходнику.** Если данные противоречат `input/avto-iz-azii-context.md` — прав источник с данными; фиксируй исправление в `discovery/changes-log.md` (что было → что стало → почему → источник).
5. **Актуальность.** Сейчас 2026 год. Законы, пошлины, утильсбор, курсы, санкционные и экспортные ограничения меняются — ищи актуальные на 2025–2026, указывай дату данных.
6. **Язык** — русский, простой, без канцелярита. Документы — Markdown.
7. **Связь с презентацией.** В начале каждого артефакта строка: `Для слайдов: …` — каким слайдам ТЗ он служит.

## Ревью каждого шага

После создания артефактов шага запусти **отдельного сабагента-ревьюера** (Agent tool, general-purpose): передай ему пути к артефактам шага, `input/`-файлы, путь к `PIPELINE.md` с чек-листом этого шага и общий чек-лист. Ревьюер не правит файлы, а пишет `reviews/<ID шага>-review.md`: вердикт `PASS` или `FAIL`, список проблем с конкретными правками.

- `PASS` → шаг `DONE`.
- `FAIL` → исправь проблемы и запусти ревью снова. Максимум 2 цикла исправлений. Если после них всё ещё `FAIL` — статус `DONE_WITH_ISSUES`, нерешённое перечисли в заметках `STATUS.md` и в разделе «Открытые вопросы» артефакта. Не застревай.

## Лимиты

- Если получил ошибку лимита использования (usage limit, rate limit, 429, повторяющееся overloaded) — **не продолжай в цикле и не жди sleep'ами**. Закоммить и запушь всё готовое и заверши запуск. Следующий запуск по расписанию (раз в час) продолжит, когда лимит обновится. Блокировка сама устареет через 100 минут.
- Экономь: не перечитывай большие файлы без нужды, веб-поиск — прицельно.
